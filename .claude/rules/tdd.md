# TDD Rule

> **이 규칙은 Rigid다 — 상황에 맞게 변형하지 마라.** "이번만 예외로", "일단 코드부터"는 허용되지 않는다. 예외가 필요하다고 느껴진다면 아래 "적용 기준"과 "변명 차단표"를 먼저 확인하라.

**우선순위 조항:** 프로젝트의 `CLAUDE.md` / `AGENTS.md`에 TDD 관련 규칙이 명시되어 있다면 그 규칙이 이 파일보다 **우선**한다. 이 파일은 프로젝트별 규칙이 없을 때 적용되는 **기본값(fallback)** 이다.

## 1. 적용 기준

**반드시 TDD를 적용해야 하는 대상**

- **비즈니스 로직** (계산, 상태 전이, 조건 분기가 있는 모든 코드)
- **API 엔드포인트 / 핸들러** (요청-응답 계약이 있는 코드)
- **유틸리티 함수** (순수 함수, 변환/파싱/검증 로직)
- **버그 수정** (버그를 재현하는 실패 테스트가 먼저, 수정은 그다음)

**TDD가 불필요한 대상**

- **타입 정의** (인터페이스, 타입 별칭 — 동작이 없다)
- **설정 파일** (`vite.config.ts`, `eslint.config.js`, `tsconfig.json` 등)
- **순수 UI/마크업** (로직 없는 프레젠테이션 컴포넌트, 스타일)
- **SQL / 마이그레이션 스크립트** (선언적 스키마 변경)

애매한 경우 기본값은 **"적용한다"** 쪽이다.

## 2. RED-GREEN-REFACTOR 사이클

### RED

- **하나의 동작(behavior) = 하나의 테스트.** 여러 동작을 한 테스트에 묶지 않는다.
- 테스트를 작성한 즉시 **반드시 실행해서 실패를 눈으로 확인**한다. 실행하지 않고 넘어가는 것은 RED가 아니다.
- 실패 이유는 반드시 **"기능이 아직 구현되지 않았기 때문"** 이어야 한다. 문법 오류, import 누락, 오타로 인한 실패는 RED로 인정하지 않는다 — 고치고 다시 실행해 올바른 이유로 실패하는지 확인하라.

### GREEN

- 테스트를 통과시키는 데 필요한 **최소한의 코드만** 작성한다.
- **YAGNI**: 지금 테스트가 요구하지 않는 기능, 파라미터, 분기를 미리 만들지 않는다.
- 코드 작성 후 **신규 테스트와 기존 테스트 전체가 통과**하는 것을 확인한다. 신규 테스트만 통과하고 회귀를 확인하지 않는 것은 GREEN이 아니다.

### REFACTOR

- 중복 제거, 이름 개선, 헬퍼/모듈 추출을 수행한다.
- 리팩터링 동안 **테스트는 계속 green을 유지**해야 한다. 한 스텝이라도 깨지면 되돌리고 더 작은 단위로 나눈다.
- 이 단계에서 **새로운 동작을 추가하지 않는다.** 새 동작이 떠올랐다면 적어두고 다음 사이클의 RED로 넘긴다.

### 반복

- REFACTOR가 끝나면 **다음 동작에 대한 RED로 돌아간다.** 사이클은 대상 기능이 끝날 때까지 반복한다.

## 3. 삭제 강제 규칙

- 테스트보다 **프로덕션 코드를 먼저 작성했다는 사실을 발견하면, 그 코드를 삭제**하고 RED부터 다시 시작한다.
- "일단 참고용으로 남겨두고 테스트만 나중에 맞추기"는 **금지**한다. 주석 처리, 다른 파일로 이동, `_backup`류 이름 변경 등 모든 형태의 우회 보존도 동일하게 금지한다.

## 4. 변명 차단표

| 변명 | 반론 |
|---|---|
| "너무 단순해서 테스트 불필요" | **단순한 코드일수록 테스트 작성 비용도 낮다.** 단순함은 테스트를 건너뛸 이유가 아니라 테스트를 빨리 끝낼 이유다. 단순해 보이는 로직이 가장 먼저 조용히 깨진다. |
| "나중에 추가하겠다" | **"나중"은 오지 않는다.** 코드가 GREEN 상태로 넘어가는 순간 테스트를 추가할 압력이 사라진다. 지금 없는 테스트는 영원히 없는 테스트다. |
| "시간이 없다" | **TDD를 건너뛴 코드는 디버깅 시간으로 그 대가를 지불한다.** 지금 아끼는 시간은 나중에 몇 배로 되돌아온다. |
| "삭제하면 낭비" | **테스트 없이 작성된 코드는 검증되지 않은 코드다.** 이미 작동한다고 "느껴지는" 것과 테스트로 증명된 것은 다르다. 낭비는 코드가 아니라 검증되지 않은 코드를 신뢰하는 것이다. |
| "프로토타입이다" | **프로토타입은 프로덕션이 된다.** "프로토타입이니까"로 시작한 코드가 예외 없이 그대로 배포된다. 버릴 게 확실하면 애초에 별도 브랜치/디렉터리에서 격리하고, 남길 코드라면 TDD를 적용하라. |
